# План исправлений прошивки ESP32 CNC

> Составлен по фактическому состоянию кода: коммит `e261e53`, 2026-09-15.
> Подробное описание текущего поведения — в [README.md](README.md), раздел 11.
>
> **Легенда приоритетов**
>
> - **P0** — блокирует запуск или создаёт риск для станка/оператора. Без этого нельзя включать шпиндель.
> - **P1** — влияет на точность, плавность и надёжность движения. Нужно до первой реальной обработки.
> - **P2** — функциональность, протокол, удобство эксплуатации. Можно делать после P0–P1.
> - **P3** — гигиена кода, тесты, документация.
>
> Формат: `- [ ]` — сделать, `- [x]` — готово. После выполнения пункта желательно дописать в конце строки дату и коммит.

## Сводка

| Приоритет | Кол-во | Смысл |
|---|---:|---|
| P0 | 9 | сборка, безопасность, аварийные остановки, координатная база |
| P1 | 9 | таймер, ядра, конвейер кадров, ограничения скоростей, сканы |
| P2 | 12 | команды, протокол, парсеры, конфиг, шпиндель |
| P3 | 4 | тесты, комментарии, неиспользуемые поля, документация |

**Рекомендуемый порядок:** P0 → P1-1…P1-5 → P1-6…P1-9 → P2 → P3. Пункты P0-2 и P0-6 делать вместе: они меняют одну аварийную ветку.

## P0 — блокеры и безопасность

  `platformio.ini:12`, `src/main.cpp:41–44`.

- [ ] **P0-2 · Убрать `changeState()` из таймерного ISR.**
  `src/motion.cpp:581–601`, `src/state_manager.cpp:53–58`.
  Из прерывания вызывается `changeState(STATE_ALARM)`, который пишет в `Preferences` (Flash) и печатает в `Serial`. Это может зависнуть/повредить NVS и блокирует ISR.
  **Действие:** ISR только обесточивает драйверы, сбрасывает буфер и выставляет `volatile`-флаг `alarmRequested`; `loop()`/отдельная задача выполняет `changeState()` и сохранение. Убрать `Serial` из пути ISR, добавить критическую секцию/атомарные операции.
  **Готово, когда:** в ISR нет `Preferences`, `Serial`, `String`; авария по ESTOP/MOTORS_ALARM/концевику доходит до `ALARM` в `loop()`.

- [ ] **P0-3 · Проверять результат `changeState()`.**
  `src/wifi_manager.cpp:182, 186, 190, 205, 209–211, 224, 230, 245`; `src/gcode_program.cpp:225`.
  `changeState()` возвращает `void`; при запрещённом переходе (нет хоуминга, `ALARM`) команда всё равно выполняется и может начать движение.
  **Действие:** сделать `bool changeState(MachineState)`, возвращать `false` при запрете; в обработчиках команд при отказе выдавать `ERROR: ...` и **не** вызывать движение. Для `START_PROGRAM` дополнительно проверять `isHomed`, `totalLoadedCommands > 0`, отсутствие `ALARM`.
  **Готово, когда:** `JOG`, `SCAN_GEOMETRY`, `START_PROGRAM` без хоуминга не двигают станок и возвращают ошибку.

- [ ] **P0-4 · Синхронизировать `plannerSteps*` и `currentSteps*`.**

  **Действие:** ввести `syncPlannerToActual()` (`plannerSteps* = currentSteps*`) и вызывать её перед JOG, `START_PROGRAM`, `START_FROM_LINE`, после любого аварийного останова и после `SET_HOMED_DEBUG`. Не обнулять `currentSteps*` без физического движения.
  **Готово, когда:** после `ESTOP → RESET_ALARM` и после `SET_HOMED_DEBUG` JOG едет ровно на заданную величину.

- [ ] **P0-5 · Защитить хоуминг.**

## P1 — движение, точность, производительность

- [ ] **P1-1 · Вернуть 200 кГц и проверить железо.**
  `src/main.cpp:40–44`, `src/motion.cpp:310, 156`.

  **Действие:** вынести частоту в константу, вернуть 5 мкс, пересчитать `BASE_CNC_FREQ`; замерить загрузку CPU, джиттер ISR, минимальную ширину STEP драйверов, потери шагов и нагрев на X/Y/Z. При проблемах — промежуточные 150 кГц или аппаратный генератор.

- [ ] **P1-2 · Разнести `loop` и `motionTask` по ядрам.**

  **Действие:** перенести `loop` на Core 0 (`-DARDUINO_RUNNING_CORE=0` или отдельная задача), `motionTask` оставить на Core 1; проверить `nextSeg`/флаги на гонки, добавить `volatile`/атомарные/критические секции; замерить джиттер.

- [ ] **P1-3 · Сделать потоковый конвейер кадров (look-ahead).**
  `src/main.cpp:85–89`; `src/motion.cpp:165–170`; `src/gcode_program.cpp:81–143`.
  Следующий кадр запрашивается только после полного опустошения кольца (`!isPlannerBusy`), поэтому на каждом стыке станок останавливается и стартует с `v_start`.
  **Действие:** разрешить очередь из 2–4 кадров, запрашивать следующий при заполнении буфера ниже high-water mark; сохранять непрерывность `v_end` предыдущего и `v_start` следующего; не сбрасывать `isPlannerBusy` до фактического слива; проверить порядок с `HOLD`.
  **Готово, когда:** длинная УП из коротких кадров выполняется без остановок на стыках; осциллограмма STEP не показывает разрывов.

- [ ] **P1-4 · Ограничить скорости и защитить математику.**
  `src/motion.cpp:250–430`.

  **Действие:** клампы `v_start/v_end/v_frame` в `[minVectorSpeed, v_max]`; `v_max <= 0` → ошибка кадра, а не 344 мс; `delay` в `uint32_t` с верхним пределом; проверка `isfinite` для всех float из пакета.
  **Готово, когда:** пакет с `F=0`, отрицательным `F`, `NaN`, `v_start > F` не двигает станок и отклоняется с ошибкой.

  **Готово, когда:** `HOLD` → `RESUME` не меняет итоговую координату; после `RESET_ALARM` из `HOLD` нет медленного «ползка».

## Критерии приёмки по этапам

**После P0**

- `pio run` собирается на зафиксированной версии ядра.
- `ESTOP`, `MOTORS_ALARM`, обрыв концевика → `ALARM`, движение прекращается, повторный старт требует `RESET_ALARM` + хоуминга.
- JOG/SCAN/START без хоуминга отклоняются.
- После `RESET_ALARM`, `SET_HOMED_DEBUG` и `ESTOP` JOG едет ровно на заданную величину.
- Выход за soft limits отклоняется.
- JOG/SCAN используют согласованные единицы.

**После P1**

- 200 кГц (или обоснованно промежуточная частота), нет потери шагов и джиттера.
- `loop` и `motionTask` на разных ядрах.
- Длинная УП идёт без остановок на стыках кадров.
- `HOLD/RESUME` не меняет итоговую координату, нет «ползущих» шагов.
- Сканы не блокируют `ESTOP` и телеметрию.
- Карта провиса не выходит за массив.

**После P2**

- `START_FROM_LINE` и Single Block работают.
- Серия JOG выполняются подряд.
- Некорректный конфиг/пакет отклоняется без движения.
- GUI и прошивка проходят совместный сценарий заливки/старта/паузы/остановки.

**После P3**

- Есть автоматические тесты математики и парсеров.
- Комментарии, README и конфиг соответствуют коду.
