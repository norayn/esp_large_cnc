# 4. Генерация шагов и буферизация

> Часть паспорта прошивки. Оглавление — [INDEX.md](INDEX.md).
> **Читать перед:** правками планировщика, `motionTask`, ISR, кольцевого буфера, HOLD/OVERRIDE.
> **Источник истины:** `src/motion.cpp`, `src/motion.h`.

## 4.1 Структуры и память

Каждая ячейка времени — 4 байта (7 битовых полей, выравнивание по 32 бита):

```cpp
struct StepCmd {
    uint32_t stepX : 1; // 1 = импульс STEP HIGH
    uint32_t dirX  : 1; // 1 = HIGH
    uint32_t stepY : 1;
    uint32_t dirY  : 1;
    uint32_t stepZ : 1;
    uint32_t dirZ  : 1;
    uint32_t valid : 1;
};
```

- `STEP_BUFFER_SIZE = 4096` → **16 КБ** статической SRAM.
- `BinaryCommand` — `__attribute__((packed))`, **27 байт**: `uint8_t` + `uint16_t` + 6 × `float` (`x, y, z, f, v_start, v_end`).
- `gcodeBuffer` — статический массив **2000 × 27 = 54 КБ** (не «динамическая куча»).
- `curvatureMap` — 250 точек × 8 байт = **2 КБ**.

Итого только под эти структуры — около 72 КБ статической памяти.

## 4.2 Межзадачный обмен

`prepareVectorSegment()` (Core 0, `supervisorTask`) заполняет `nextSeg` под `xferMux` и взводит `hasNewData` + `isPlannerBusy` + `isVectorMoving`. `motionTask` на Core 1 забирает кадр под тем же локом, сразу сбрасывает `hasNewData` (handshake), взводит `isMotionGenerating` и генерирует такты. `isPlannerBusy` снимается только когда **и новых данных нет, и кольцевой буфер полностью пуст**.

## 4.3 Планировщик кадра

Для каждого кадра:

1. Пересчёт миллиметров в шаги, вычитание прошлой математической базы `plannerSteps*`.
2. Оптическая поправка провиса по **целевой** X кадра.
3. Разбиение вектора на 3 сегмента: разгон / круиз / торможение (короткий вектор — треугольный профиль без круиза).
4. Целочисленная валидация: `dX[0]+dX[1]+dX[2] == totalDeltaX`; расхождение округления принудительно добавляется в сегмент торможения.
5. Потактовый Брезенхем по ведущей оси; частота считается от `currentVelocity` и `maxSegmentSteps / totalLength_mm`.
6. Запись пустых/рабочих ячеек в кольцо; при заполнении — `vTaskDelay(1)`.

Основные параметры профиля: `v_frame` (подача), `accel = cfg.maxAcceleration`, `v_start`/`v_end` от Look-Ahead ПК. Скорости на стыках рассчитывает **Python-планировщик GUI**, ESP32 их не пересчитывает.

## 4.4 ФАКТ: конвейер кадров

> **⚠ Отличие:** следующий кадр запрашивается только при `isPlannerBusy == false`, то есть после **полного опустошения** кольцевого буфера. Между кадрами возникает пауза: станок успевает замереть, а следующий кадр стартует с `v_start`, которая может быть десятки мм/с. Заявленный непрерывный Look-Ahead и «подушка 40 мс» на стыках кадров фактически не работают. Задача — P1-3 в [TODO.md](../TODO.md).

## 4.5 ISR

- Каждый вызов: если `motionStopRequested` — только опустить STEP и выйти; иначе проверка ESTOP/ALARM/концевиков через `safety*Active()` (при `SAFETY_INPUTS_ENABLED=0` это константа `false`, `digitalRead` не вызывается), затем одна фаза.
- HIGH: выставить DIR, поднять STEP, инкрементировать `currentSteps*`; LOW: опустить STEP.
- Реальных вычислений с плавающей точкой нет.
- При аварии — `emergencyStopFromISR()`: обесточивание, сброс очереди, флаги. Никаких `changeState()`/`Preferences`/`Serial`/`String`.
- При пустом буфере `isVectorMoving = false`.

## 4.6 HOLD / RESUME / OVERRIDE

- `updateFeedrateFading()` вызывается в `supervisorTask` на каждом круге, но внутри ограничена периодом 5 мс.
- `OVERRIDE=<0.1…2.0>` плавно меняет `pythonFeedrateOverride`; множитель применяется при **генерации** ячеек (задержка до заполнения буфера).
- При `HOLD` включается `virtualSpeedLimit`, который уменьшается с темпом `cfg.maxAcceleration` (при 10 мм/с — порядка 60–70 мс, а не фиксированные 300 мс). При достижении нуля генератор встаёт в цикл ожидания.
- `RESUME` выводит из ожидания и **не очищает** кольцевой буфер: уже рассчитанные шаги доигрываются, DDA продолжает с текущего индекса, итоговая координата не меняется.
- `HOLD → IDLE/ALARM` теперь останавливает движение: `changeState()` вызывает `requestMotionStop()`, генератор видит флаги, таймер выключается, очередь очищается. «Ползка» на 0,1 мм/с после остановки нет.
- `STOP` — явная мягкая остановка: снять генерацию, очистить очередь, остаться в `IDLE`, сохранить `isHomed`.

## 4.7 Краевые случаи математики

- Если `v_start > v_max` или `v_end > v_max`, длины сегментов становятся отрицательными, доли `pct_*` — отрицательными, и первый сегмент может поехать **в обратную сторону**. Клампов нет (P1-4).
- При `v_max = 0` частота упирается в нижний предохранитель 1 Гц, шаг растягивается до 100 000 ячеек = **1 с**; счётчик ячеек теперь `uint32_t`, переполнения 16 бит нет.
- Нижний предел эффективной скорости — 0,1 мм/с; верхний — 1 ячейка на шаг.
