# 1. Архитектура и распределение задач (FreeRTOS)

> Часть паспорта прошивки. Оглавление — [INDEX.md](INDEX.md).
> **Читать перед:** правками `src/main.cpp`, задач, приоритетов, мьютексов, `CNC_TIMER_TICK_US`.
> **Источник истины:** `src/main.cpp`, `src/motion.h`, `src/motion.cpp`.

## 1.1 Проектная топология

- **Core 0 — супервизор:** `supervisorTask` (Arduino `loop()` пустой), Wi-Fi TCP, USB-UART, FSM, приём и буферизация УП, телеметрия.
- **Core 1 — движение:** высокоприоритетная задача `motionTask` (DDA/Брезенхем) и аппаратный таймер шагов.
- Обмен кадрами — через очередь кадров `frameQueue` (под `xferMux`) и кольцевой буфер тактов `stepRingBuffer`.

## 1.2 ФАКТ: фактическое распределение

- **Core 0 — `supervisorTask`** (`xTaskCreatePinnedToCore`, приоритет 1, стек 8192): `checkHardwareSecurity()`, FSM-команды из USB/Wi-Fi, телеметрия, приём карт, выдача следующего кадра УП, `updateFeedrateFading()`, `updateLaserMapCommunication()`, `updateScanTask()` (один шаг скана за круг, [geometry.md §5.4](geometry.md#54-комплексное-сканирование-геометрии)).
- **Core 1 — `motionTask`** (`xTaskCreatePinnedToCore`, приоритет 24, стек 8192): DDA/Брезенхем, заполнение `stepRingBuffer`.
- **Core 1 — таймерный ISR**: `timerAttachInterrupt()` вызывается из `setup()`, а `setup()`/`loopTask` остаются на Core 1 (`ARDUINO_RUNNING_CORE = 1`). Поэтому ISR не переезжает на Core 0 вместе с супервизором. Если перенести `setup` на Core 0, ISR тоже уедет туда — это важно при будущих изменениях.
- Arduino `loop()` оставлен пустым (`vTaskDelay`): вся прикладная работа в `supervisorTask`, чтобы `loopTask` не конкурировал с генератором.

**Межъядерная синхронизация (P1-2):**

- `xferMux` защищает межъядерную очередь кадров `frameQueue` (producer — Core 0, consumer — `motionTask`). Индексы и счётчик меняются в одной критической секции, поэтому недописанный кадр другое ядро не увидит.
- `ringMux` защищает индексы/ячейки `stepRingBuffer` и снимок `plannerSteps*` при обмене Core 0 ↔ Core 1 (хоуминг, `requestMotionStop()`).
- `isMotionGenerating` показывает, что `motionTask` реально пишет шаги. `requestMotionStop()` сначала очищает очередь кадров, ждёт сброса флага (до 100 мс), и только потом очищает кольцо и синхронизирует `plannerSteps*` с `currentSteps*`. Это закрывает гонку «стоп во время генерации кадра».
- `motionTask` пишет кольцо на том же ядре, что и ISR, поэтому отдельный лок ему не нужен; ISR берёт `ringMux` только против Core 0.
- `isGeneratorSuspendedOnHold`, `virtualSpeedLimit`, `smoothedFeedrateOverride`, `sharedCurrentVelocity` объявлены `volatile`.

> **⚠ Ограничение измерений:** джиттер STEP и загрузку Core 1 нужно проверять на реальном станке/осциллографом. В прошивке нет счётчика джиттера; при старте печатаются фактические ядра `setup`, `supervisorTask` и `motionTask`.

## 1.3 Таймер и сетка времени

| Параметр | Проект | ФАКТ |
|---|---|---|
| `timerBegin(0, 80, true)` | делитель 80 → 1 МГц | 1 МГц |
| `timerAlarmWrite(..., CNC_TIMER_TICK_US, ...)` | 5 мкс (200 кГц) | **5 мкс (200 кГц)** |
| Фаза ISR | одна фаза за вызов | HIGH/LOW по очереди (2 тика на ячейку) |
| Потребление ячейки буфера | 10 мкс | **10 мкс** |
| Максимальная частота шагов | 100 кГц на ось | **100 кГц на ось** |
| Подушка буфера 4096 ячеек | 40,96 мс | **40,96 мс** |

> Частота задаётся одним макросом `CNC_TIMER_TICK_US` в `motion.h`; `CNC_CELL_HZ = 1 000 000 / (2 × CNC_TIMER_TICK_US) = 100 000` выводится из него, поэтому таймер и математика профиля не разъезжаются. При 200 кГц ISR вызывается 200 тыс. раз/с; реальный джиттер, ширину STEP у драйверов и запас CPU нужно измерить на железе — счётчика в прошивке нет.

Максимальные скорости при сетке 100 кГц: X ≈ 1000 мм/с (100 шаг/мм), Y/Z ≈ 250 мм/с (400 шаг/мм). Это аппаратный потолок выдачи, а не рабочие подачи.
