## 2. Геометрия, кинематика и механика

Конструкция рассчитана на жёсткую обработку протяжённых деталей (до 4 м) и собрана на пространственной сварной ферме.

- **Ось X (4000 мм, ведущая):** рейка—шестерня, `stepsPerMmX = 100.0`. Высокие скорости холостого хода, отсутствие провиса длинного ШВП. По X перемещается тяжёлая чугунная каретка со шкафом автоматики, поэтому ускорение ограничено (`maxAcceleration = 150.0 мм/с²`).
- **Оси Y (500 мм) и Z (200 мм):** направляющие «ласточкин хвост», трапецеидальные винты, `stepsPerMmY/Z = 400.0`. Механический поджим пружинами для выборки люфта. Из-за высокого трения покоя стартовая скорость вектора задана повышенной (`minVectorSpeed = 2.0 мм/с`), чтобы драйверы не уходили в Alarm.
- **Кареточное размещение шкафа:** драйверы, ESP32, датчики и БП закреплены на подвижной каретке. Сигнальные линии STEP/DIR, UART2 к ESP32-CAM и датчики короткие (<1 м) и неподвижны относительно шкафа; в кабель-треке — только сетевой кабель питания класса High-Flex.

Диапазоны `minX…maxZ` в конфиге **проверяются** в `validateMachineTarget()` — см. [fsm-safety.md §3.6](fsm-safety.md#36-программные-лимиты-soft-limits).

## 5.1 Рабочая система координат (WCS / G54)

- `SET_ZERO:X|Y|Z|ALL` фиксирует текущую машинную позицию как ноль детали и сохраняет смещения в NVS.
- В кадре: `machine = cmd + wcsOffset`, затем (если включён наклон) добавляются поправки Y/Z.
- Телеметрия отдаёт координаты детали: `(currentSteps / stepsPerMm) - wcsOffset`.

## 5.2 Программный разворот заготовки (точки A/B)

- Оператор фиксирует точки A и B (`SET_ALIGN_A/B`), затем `ACTIVATE_ALIGN`.
- При `|ΔX| ≥ 10 мм` считаются `slopeY = ΔY/ΔX`, `slopeZ = ΔZ/ΔX`; значения и флаг сохраняются в NVS.
- При активном наклоне для G0/G1: `Y += (machineX - A.x) * slopeY`, `Z += (machineX - A.x) * slopeZ`.
- `DEACTIVATE_ALIGN` выключает коррекцию и сохраняет флаг.

> **⚠** Коррекция применяется только к кадрам УП. JOG, `SCAN_GEOMETRY` и `START_CALIBRATION` её не используют (вопреки прежнему описанию). См. P2-12.

## 5.3 Оптическая карта провиса фермы

- Таблица `curvatureMap[250]`; по умолчанию `laserMapSize = 201`, `laserGridStep = 20 мм` → зона 0…4000 мм.
- Линейная интерполяция между соседними точками; X ограничивается `[0, (size-1)*gridStep]`.
- Поправка Y/Z считается в `motionTask` по **конечной** X кадра. Чтобы внутри длинного кадра не терять изгибы карты, фидер режет кадр УП и `JOG` на куски не длиннее одного интервала `laserGridStep`: внутри куска карта линейна, поэтому поправка на его концах точна, а на границах кусков ступеньки нет.
- Источники карты: `MAP_LOAD:IDX=…;Y=…;Z=…` с ПК или `START_CALIBRATION` — проход камерой по точкам `X = i × laserGridStep`, `i = 0…laserMapSize-1`, с записью в `curvatureMap[i]`.
- `updateLaserMapCommunication()` — единственный читатель `Serial2`: разбирает `OFFSET: Y=…; Z=…` и складывает результат в `lastCam*`, откуда его забирает скан через `takeCamResponse()`. **Живого контура нет (P1-9):** камера опрашивается только командой `MEASURE` в фазе замера скана или калибровки, во время реза её ответы не читаются и текущий кадр не меняют. Поправка Y/Z на ходу берётся исключительно из `curvatureMap`.

`START_CALIBRATION` идёт тем же движком, что и скан геометрии (§5.4): позиционирование → пауза → `MEASURE` → запись точки. Параметры берутся из конфига, поэтому калибровка не начинается, если `laserMapSize` вне `1…250`, `laserGridStep ≤ 0` или последняя точка `(laserMapSize-1) × laserGridStep` вне поля.

**Границы карты (P1-7).** `validateCurvatureConfig()` требует `1 ≤ laserMapSize ≤ 250` и конечный `laserGridStep > 0`; `SET_CONFIG` с другими значениями отклоняется с `ERROR`, битые значения в NVS при старте заменяются дефолтами из `CONFIG_FIELDS`. `updateCurvaturePoint()` дополнительно проверяет индекс по размеру массива и `isfinite` смещений, а `getCorrection()` при нерабочем конфиге возвращает нулевую поправку и не делит на ноль (`laserMapSize = 1` — карта из одной точки).

## 5.4 Комплексное сканирование геометрии

`SCAN_GEOMETRY:<START>;<END>;<STEP>;<SPEED>` (`SPEED` — мм/мин, допустимо 1…20000). Скан и калибровка карты (§5.3) выполняются одним движком `src/scan_task.cpp`; за один вызов `updateScanTask()` из `supervisorTask` делается не больше одной фазы, поэтому `loop()` не блокируется.

Фазы на каждую точку:

1. **`POSITION`** — `X = START + i × STEP` (для карты — `i × laserGridStep`); каждая точка проверяется `validateMachineTarget()`, кадр ставится `prepareVectorSegment(X, 0, 0, SPEED, …)` в **машинных** координатах, без WCS/наклона; поверх Y/Z всё равно накладывается лазерная поправка, если карта непустая.
2. **`MOVE`** — ожидание `isPlannerBusy == false` (очередь кадров и кольцо пусты, станок физически стоит).
3. **`SETTLE`** — пауза **600 мс** на гашение вибраций фермы; здесь же читается щуп (`readDialIndicator`, до ~100 мс, только для `SCAN_GEOMETRY`) и отправляется `MEASURE`.
4. **`MEASURE`** — ожидание ответа камеры через `takeCamResponse()`, таймаут **1500 мс**; ответ учитывается только пришедший после запроса. Таймаут не прерывает скан: точка помечается `NO CAMERA RESPONSE`, калибровка карты её пропускает.

Параметры проверяются **до** `changeState(STATE_CALIBRATION)`: `START/END/STEP/SPEED` конечны, `STEP > 0`, `END > START`, число точек `(END-START)/STEP + 1` не больше **2000**, крайние точки внутри поля.

Выдача в `Serial` и Wi-Fi: `X;DIAL_INDICATOR;LASER_Y;LASER_Z` (без префикса) для скана геометрии и `DATA: Point <i> -> Y=…, Z=…` для калибровки карты. `STOP`, `ESTOP`, `ALARM` и `RESET_ALARM` меняют состояние, и движок закрывается строкой `=== SCAN ABORTED ===`, не возобновляя движение.

> **⚠** GUI ожидает строки `SCAN:<x>;<z>;<type>` — форматы не совпадают (P2-7).

## 5.5 Цифровой индикатор (24-битный протокол)

- `INDICATOR_CLK = GPIO18`, `INDICATOR_DATA = GPIO19`, `INPUT_PULLUP`.
- Ожидание старта (CLK LOW) — таймаут 50 мс; далее 24 бита по спаду CLK, таймауты 1 мс на фронт.
- Бит с индексом 20 — знак; биты 0…19 — величина; результат `value * sign / 100.0` мм.
- При обрыве/таймауте — `-999.0` (в CSV выводится `DISCONNECTED`).
