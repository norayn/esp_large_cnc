## Сценарии

### Подключение

1. Открыть TCP/USB, дождаться `connection_status`.
2. Отправить `GET_CONFIG`, разобрать `CONFIG_DATA:` в `machine_state`.
3. Дождаться первого `<Status:...>` и только после него включать кнопки.
4. Показывать `Hom:0` как «NOT HOMED», а не как ошибку связи.

### Хоуминг

- `HOME` или `$H` — только из `IDLE` ([§3.2](fsm-safety.md#32-переходы-и-блокировки)).
- На время `HOMING` заблокировать JOG/START; `STOP`/`ESTOP` оставить.
- Движение включать после `Hom:1` и `IDLE`.

### JOG

- Только из `IDLE`; цель — абсолютная координата (`текущая WCS ± шаг`), `F` — мм/мин ([§6.4](protocol.md#64-команды-режима-idle)).
- Один JOG за раз: следующий отправлять после `IDLE` в телеметрии; очередь JOG в прошивке не поддерживается.
- `JOGGING` снимается сам, `RESET_ALARM` не нужен. До хоуминга JOG разрешён при `allowJogBeforeHoming=true`, но координаты не привязаны к станку — предупредить оператора.

### Заливка УП

1. Проверить число кадров локально: `MAX_COMMANDS_BUFFER = 2000`, больше — предложить разбить файл. `LINE` — `uint16_t`.
2. `GCODE_UPLOAD_START` → дождаться `STATUS: Ready`; с этого момента кнопки движения заблокированы.
3. Спланировать G-код: `G0` → type 0, `G1` → type 1, `M3`/`M5`/`M8`/`M9` → 3/5/8/9; остальные M не отправлять. Формат `B:` и единицы — [§6.5](protocol.md#65-загрузка-уп).
4. Отправлять кадры окном: ждать `ok` на предыдущие, а не заливать весь файл в сокет; на `ERROR: Add to RAM buffer failed` остановить заливку.
5. `GCODE_UPLOAD_END` → дождаться `STATUS: Upload complete. Loaded N commands.` и `ok`; сверить `N` с числом отправленных кадров.
6. Только после этого разрешать `START_PROGRAM`.

### Старт, пауза, продолжение, остановка

| Действие | Команда | Условие | Что видит GUI |
|---|---|---|---|
| Старт с начала | `START_PROGRAM` | `IDLE`, `Hom:1`, буфер не пуст | `RUNNING`, затем `Line` |
| Старт с кадра | `START_FROM_LINE:<N>` | то же | `RUNNING`; неизвестная строка — `ERROR` |
| Пауза | `HOLD` / `!` | `RUNNING`/`JOGGING` | `HOLD` |
| Продолжить | `RESUME` / `~` | `HOLD` | прежнее состояние |
| Мягкий стоп | `STOP` | не `ALARM` | `IDLE`, `Hom` сохраняется |
| Сброс аварии | `RESET_ALARM` | `ALARM` | `IDLE (LOCKED)`, нужен хоуминг |
| Аварийный стоп | `ESTOP` | всегда | `ALARM` |

- «СТОП» — это `STOP`, а не `RESET_ALARM`: последний сбрасывает `isHomed` и требует хоуминга. Текущая кнопка шлёт `RESET_ALARM` — исправить (P2-7).
- `GET_LAST_ABORTED_LINE` → `LAST_LINE:N`; после сброса аварии и хоуминга предлагать `START_FROM_LINE:N`, но помнить: станок поедет к цели кадра из текущей позиции.
- `OVERRIDE=<0.1…2.0>` — только множитель подачи, не остановка.

### Нули WCS

- `SET_ZERO:X|Y|Z|ALL` — только `IDLE`; сохраняет NVS.
- Сразу после ответа — `GET_CONFIG`, чтобы обновить `wcsOffset*` и MCS.

### Наклон A/B

- `SET_ALIGN_A`/`SET_ALIGN_B` запоминают **текущую машинную** позицию; `ACTIVATE_ALIGN` считает наклон, `DEACTIVATE_ALIGN` выключает ([§5.2](geometry.md#52-программный-разворот-заготовки-точки-ab)).
- Точки ближе 10 мм по X отклоняются, наклон не включается; сообщение уходит только в `Serial`.
- Наклон действует на кадры УП; JOG и сканы идут без него (P2-12). Кнопки «Выравнивание» не подключены (текущий клиент).

### Настройки

- `GET_CONFIG` при подключении и при открытии окна; `SET_CONFIG:<name>=<value>` — только изменённые поля ([§6.7](protocol.md#67-конфигурация)).
- `float` печатается с 2 знаками; не записывать обратно поле, которое оператор не менял.
- Валидации в прошивке почти нет (P2-5): GUI обязан ограничивать `stepsPerMm*`, `laserMapSize`, `laserGridStep`, лимиты и периоды.
- После сохранения перечитать `GET_CONFIG` и показать фактические значения, а не введённые.

### Карта провиса

- Экспорт: `EXPORT_MAP` → строки `i;x;y;z` между `=== START/END LASER MAP EXPORT ===`; сохранить CSV.
- Импорт: сначала `SET_CONFIG:laserMapSize=...` и `laserGridStep=...`, затем `MAP_LOAD_START` → строки `MAP_LOAD:IDX=<i>;Y=<...>;Z=<...>` → `MAP_LOAD_END` ([§6.6](protocol.md#66-импорт-карты-лазера)).
- Строки с индексом вне `laserMapSize` молча игнорируются; проверять размер до импорта.

### Сканы

- `START_CALIBRATION` — калибровка карты по `laserMapSize`/`laserGridStep`; `SCAN_GEOMETRY:<START>;<END>;<STEP>;<SPEED>` — скан геометрии ([§5.4](geometry.md#54-комплексное-сканирование-геометрии)).
- Обе команды сразу отвечают и работают в `supervisorTask`: телеметрия, `STOP`, `ESTOP` доступны всё время.
- Строки: `=== START ... ===`, голый CSV `X;DIAL_INDICATOR;LASER_Y;LASER_Z` (геометрия), `DATA: Point i -> Y=..., Z=...` (карта), `=== END ... ===` / `=== SCAN ABORTED ===`; `DISCONNECTED` — нет связи с датчиком.
- Текущий клиент ищет `SCAN:` и теряет строки (P2-7).

### Single Block

`SINGLE_BLOCK_ON/OFF` есть, `NEXT_BLOCK` нет (P2-2): после включения программа встаёт навсегда; в UI не выводить.

## Блокировки UI по состояниям

| `Status` | Разрешено | Запрещено |
|---|---|---|
| `DISCONNECTED` | подключение | всё остальное |
| `INIT`, `INIT (LOCKED)` | `GET_CONFIG`, телеметрия | движение |
| `IDLE (LOCKED)`, `Hom:0` | `HOME`, `SET_ZERO`, `JOG` при `allowJogBeforeHoming` | `START_PROGRAM`, `START_CALIBRATION` |
| `IDLE`, `Hom:1` | все команды `IDLE` | — |
| `RUNNING` | `HOLD`, `STOP`, `ESTOP` | `START_PROGRAM`, JOG, `SET_CONFIG` |
| `HOLD` | `RESUME`, `STOP`, `ESTOP` | JOG, старт |
| `JOGGING` | `STOP`, `ESTOP` | новый JOG до `IDLE` |
| `HOMING` | `ESTOP` | `STOP` (только после цикла), JOG, старт |
| `CALIBRATION` | `STOP`, `ESTOP` | JOG, старт, конфиг |
| `GCODE_UPLOAD` | `B:`, `GCODE_UPLOAD_END` | всё, кроме глобальных |
| `MAP_TRANSFER` | `MAP_LOAD:*`, `MAP_LOAD_END` | всё, кроме глобальных |
| `ALARM` | `RESET_ALARM`, `ESTOP` | всё остальное |

- Источник переходов — [fsm-safety.md §3.2](fsm-safety.md#32-переходы-и-блокировки). Прошивка ответит `ERROR: Unknown or blocked command`, но UI не должен предлагать заведомо заблокированную кнопку.
- `IDLE (LOCKED)` — это `IDLE` + `!isHomed`; сравнивать базовое состояние до пробела. `SET_HOMED_DEBUG` снимает блокировку без хоуминга — только для стенда. `HOMING` блокирующий: `STOP` обработается после цикла.

## Ошибки, логи, восстановление

- Логировать обе стороны с временем и направлением; файл — `cnc_session.log`.
- `ERROR:` показывать оператору, а не только в терминал; не превращать в «команда выполнена».
- После `RESET_ALARM` принудительно показать «NOT HOMED» и заблокировать старт.
- После `STOP` программа сама не продолжается: `START_PROGRAM` начнёт с 0, `START_FROM_LINE:<N>` — с указанного кадра.
- После обрыва: `DISCONNECTED`, координаты помечены как устаревшие, движение запрещено; после переподключения — `GET_CONFIG` и ожидание телеметрии.

## Приёмка

Сценарий с прошивкой (критерий P2-7):

1. Подключение по Wi-Fi и USB, `GET_CONFIG`, телеметрия, `Hom`.
2. Хоуминг, серия JOG, возврат в `IDLE`, нули WCS.
3. Заливка УП на 2000 кадров и отказ на 2001-м.
4. Старт, `HOLD`, `RESUME`, `STOP`, повторный старт; `RESET_ALARM` требует хоуминга.
5. Экспорт и импорт карты, скан геометрии и калибровка с графиком.
6. Обрыв и переподключение без ложного «выполнено».
7. `SAFETY_INPUTS_ENABLED = 1`, `ESTOP` в `RUNNING` и `JOG`.
